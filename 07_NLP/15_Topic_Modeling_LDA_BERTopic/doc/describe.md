# 15. Topic Modeling: LDA, BERTopic

## Learning Objectives

- Explain LDA's generative story and what "topics" mean formally within it
- Fit an LDA model and interpret its output: topic-word and document-topic distributions
- Understand BERTopic's cluster-then-label approach as a modern alternative to LDA

## The Problem

Given a large collection of documents with no labels at all, discover the underlying themes or topics that run through the collection, and see which documents relate to which topics — a common need for exploratory analysis of large text collections (news archives, customer feedback, research papers) where reading every document individually isn't feasible. This is fundamentally an unsupervised learning problem: no labeled "topic" categories are given in advance; the structure has to be discovered directly from patterns in the text.

## The Concept

### LDA: a generative story for how documents are "created"

Latent Dirichlet Allocation (Blei, Ng, Jordan, 2003) assumes each document was generated by a specific, if fictional, probabilistic process, and works backward from the observed documents to infer the hidden ("latent") topic structure that would most plausibly have generated them:

```
LDA's generative story (how a document is IMAGINED to be created):

1. Each document has a DISTRIBUTION OVER TOPICS
   (e.g. Document A is 70% "sports", 20% "finance", 10% "politics")

2. Each topic has a DISTRIBUTION OVER WORDS
   (e.g. Topic "sports" assigns high probability to "team", "score", "player",
    low probability to "inflation", "election")

3. To generate each WORD in the document:
   a. Pick a topic according to the document's topic distribution
   b. Pick a word according to that topic's word distribution
```

No document is actually generated this way in reality, of course — this is a deliberately simplified generative model used purely as a mathematical framework. LDA's real task is **inference**: given only the observed documents (the words that actually appear), work backward to find the topic-word distributions and document-topic distributions that most plausibly would have produced them, without ever seeing the "true" topics directly (hence "latent" — hidden, inferred rather than observed).

### What LDA actually outputs

Fitting LDA to a document collection produces two things:

```
Topic-word distributions:  for each topic, a probability over the entire vocabulary
  Topic 1: {team: 0.08, score: 0.06, player: 0.05, game: 0.05, ...}
  Topic 2: {stock: 0.09, market: 0.07, inflation: 0.05, economy: 0.04, ...}

Document-topic distributions: for each document, a probability over all topics
  Doc A: {topic1: 0.7, topic2: 0.2, topic3: 0.1}
  Doc B: {topic1: 0.1, topic2: 0.6, topic3: 0.3}
```

Neither the topics nor the documents get a single hard label — every document is a *mixture* of topics, and every topic is a *distribution* over the whole vocabulary (with most words having near-zero probability under any given topic, and a handful of words carrying most of the probability mass). Interpreting a topic in practice means looking at its highest-probability words and giving it a human-readable name yourself ("this looks like a 'sports' topic based on its top words") — LDA has no concept of topic names, only word probability distributions, and the labeling step is inherently a human judgment call, not something the algorithm produces automatically.

### Fitting LDA in practice

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.decomposition import LatentDirichletAllocation

vectorizer = CountVectorizer(max_df=0.9, min_df=2, stop_words="english")
doc_term_matrix = vectorizer.fit_transform(documents)

lda = LatentDirichletAllocation(n_components=5, random_state=42)
doc_topic_matrix = lda.fit_transform(doc_term_matrix)   # document-topic distributions

feature_names = vectorizer.get_feature_names_out()
for topic_idx, topic in enumerate(lda.components_):     # topic-word distributions
    top_words = [feature_names[i] for i in topic.argsort()[-10:]]
    print(f"Topic {topic_idx}: {top_words}")
```

LDA uses a plain bag-of-words input (Lesson 02's `CountVectorizer`, not TF-IDF — LDA's generative story is specifically about raw word counts, not weighted scores), and `n_components` (the number of topics) is a hyperparameter you choose in advance, typically by trying a few values and checking which produces the most coherent, interpretable topics — there's no single "correct" number of topics for a given collection, and this choice is itself a genuine, non-trivial modeling decision.

### BERTopic: cluster embeddings, then label

BERTopic (Grootendorst, 2022) takes a different, more modern approach, built directly on the embedding techniques from Lessons 03-04 and 22: instead of a generative word-count model, it embeds each document (using a pretrained sentence embedding model, Lesson 22), reduces the embedding dimensionality (typically via UMAP), clusters the reduced embeddings (typically via HDBSCAN, a density-based clustering algorithm), and then extracts representative words for each resulting cluster (often via a class-based TF-IDF variant) to produce a human-readable topic description.

```
BERTopic pipeline:

Documents -> Sentence embeddings (Lesson 22) -> Dimensionality reduction (UMAP)
          -> Clustering (HDBSCAN) -> Extract representative words per cluster (class-TF-IDF)
```

Where LDA assigns every document a *soft mixture* over a fixed, pre-chosen number of topics, BERTopic assigns each document to a *single* cluster (documents that don't fit well into any dense cluster can be left unassigned/labeled as "outliers," rather than forced into a topic), and the number of topics emerges from the clustering process itself rather than being fixed in advance. Because it starts from semantic embeddings rather than raw word counts, BERTopic can group documents that discuss the same topic using different vocabulary (again, the same semantic-matching benefit dense retrieval had over sparse retrieval, Lesson 14) — something LDA's word-count-based generative story cannot do by construction.

| | LDA | BERTopic |
|---|---|---|
| Input representation | Raw word counts (bag-of-words) | Dense sentence embeddings |
| Document-topic assignment | Soft mixture over topics | Typically one cluster per document (or "outlier") |
| Number of topics | Chosen in advance | Emerges from clustering |
| Captures synonymy/semantics | No (word-count based) | Yes (embedding based) |
| Interpretability of topics | Top words per topic | Representative words per cluster |

## Key Terms

| Term | What it actually means |
|---|---|
| Latent Dirichlet Allocation (LDA) | A generative probabilistic topic model that infers hidden topic-word and document-topic distributions from observed word counts |
| Latent variable | A hidden, unobserved quantity (like a document's true topic mixture) that a model infers rather than directly observes |
| Topic-word distribution | The probability, under a given topic, of each word in the vocabulary appearing |
| Document-topic distribution | The probability, for a given document, of each topic being the source of its words |
| BERTopic | A topic modeling approach that clusters document embeddings and extracts representative words per cluster, rather than fitting a generative word-count model |
