# Solutions — 11 Limitations & Open Problems

1. Example: a hiring model explanation says "the model used candidate ZIP code as a strong feature" — this may be a technically accurate explanation of the model's actual behavior, but ZIP code is often a proxy for race/socioeconomic status, so relying on this "accurate" explanation to justify the decision is ethically and often legally problematic (disparate impact / proxy discrimination).

2. SHAP and LIME can disagree because they answer subtly different questions: SHAP computes exact (or TreeSHAP-approximated) game-theoretic attributions guaranteeing additivity, while LIME fits a local linear surrogate on randomly sampled perturbations — different underlying assumptions and randomness sources. The same method can also give different results on a slightly different data sample because retraining or reference-baseline choices (e.g. SHAP's background dataset, LIME's random seed) shift what "average"/"neighborhood" means, especially for correlated or high-variance features.

3. Study design: split participants into two groups. Both groups see identical wrong predictions from the model. Group A also sees a plausible-looking (but ultimately misleading) SHAP/LIME explanation for the wrong prediction; Group B sees no explanation. Then ask both groups to rate their trust in the prediction and their willingness to act on it. If Group A trusts the wrong prediction significantly more than Group B despite both being shown the same (incorrect) outcome, that demonstrates explanation-driven over-trust.

4. Conceptually: because both the model's decision boundary and post-hoc explanation methods rely on the same underlying model gradients/structure, an adversary can add a small, visually/numerically imperceptible perturbation to the input that (a) pushes the prediction to the desired wrong class while (b) simultaneously steering the SHAP/LIME attribution toward features that look "reasonable" for that class — effectively co-optimizing for a bad prediction with a good-looking cover story, without changing the input enough for a human to notice anything is off.

5. Example (Scalable XAI): one concrete next step is developing sampling-based Shapley value approximations specifically tuned for transformer attention layers, exploiting the fact that most attention weight in large models concentrates on a small subset of tokens/heads — allowing researchers to compute approximate, bounded-error Shapley attributions using only that sparse subset instead of the full parameter space, trading a small, quantifiable accuracy loss for orders-of-magnitude speedup on trillion-parameter models.
